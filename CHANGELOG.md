# get\_sybers\.cluster Release Notes

## v0\.1\.0

<a id="release-summary"></a>
### Release Summary

Initial import of the collection\. This entry was seeded by hand when antsibull\-changelog became the generator of <code>CHANGELOG\.md</code>\; it carries the <code>0\.1\.0</code> notes of the previously hand\-written Keep a Changelog file\.

<a id="added"></a>
### Added

* Containerized Ansible controller under <code>container/</code>\. A Debian trixie <code>Containerfile</code> \(same base digest as the molecule substrate\) builds an image holding <code>ansible\-core</code> 2\.21\, the Galaxy collections baked from <code>requirements\.yml</code> \(the single source of pins\)\, and the Python SDKs those collections need at runtime \(<code>proxmoxer</code>\, <code>requests</code>\) plus <code>ansible\-lint</code>/<code>yamllint</code>\. A <code>run\.sh</code> wrapper drives it on Apple\'s <code>container</code> runtime \(macOS\)\: it bind\-mounts <code>ansible/</code> so edits need no rebuild\, mounts <code>\~/\.ssh</code> read\-only\, and forwards the <code>PROXMOX\_\*</code>/<code>ANSIBLE\_\*</code> env vars\. The image runs the SSH\-based cluster plays\, <code>\-\-syntax\-check</code> and lint\; the <code>localhost</code> credential/vault plays still belong on the master node\. Built for Apple <code>container</code> but the <code>Containerfile</code> is plain OCI and builds under Docker or Podman unchanged\. Excluded from the built collection via <code>galaxy\.yml</code> <code>build\_ignore</code>\.
* Initial <code>get\_sybers\.cluster</code> collection\: Ceph mesh/tuning/diagnostics\, SDN zone/VNet setup\, audit\-logging enforcement\, node repository management\, storage network configuration\, Ludus auth/credential handling\, and PCT/packer patching\.
* Ludus server install/reconcile\. New role <code>cluster\_ludus\_install</code> and play <code>ludus\-server\-install</code> stand up a Ludus server on a Proxmox cluster node and then idempotently reconcile the SAFE keys of <code>/opt/ludus/config\.yml</code> for this cluster \(shared Ceph <code>raw</code> storage\, <code>cluster\_mode</code>\, the VXLAN <code>sdn\_zone</code>\, and the <code>reserved\_range\_numbers</code> that keep ranges off the Ceph/mesh network\, the cluster\'s storage /16\)\. <code>database\_encryption\_key</code> is captured before any edit and asserted unchanged after — it is never rewritten\; the host network keys are reconciled only on explicit <code>cluster\_ludus\_install\_manage\_network</code> opt\-in\. The ROOT API key is staged into the house credential store\, services are restarted via a single flushed handler\, and the result is verified on disk\. On a host with no install the role refuses unless <code>cluster\_ludus\_install\_run\_installer\=true</code>\, in which case it downloads and runs <code>ludus\-server \-\-no\-prompt</code> \(no reboot on an existing Proxmox host\)\. A second run is <code>changed\=0</code>\.
* New filters <code>get\_sybers\.cluster\.config\_merge</code> \(fill or overwrite a configuration mapping from discovered values\, keyed lists merged element\-wise\, null never wins\)\, <code>get\_sybers\.cluster\.config\_drift</code> \(every discovered value the configuration lacks or contradicts\) and <code>get\_sybers\.cluster\.to\_config\_yaml</code> \(the block\-style\, insertion\-ordered YAML the inventory files are written in\)\, with unit tests\.
* New play <code>cluster\-sdn\-zone</code> idempotently ensures the VXLAN SDN zone \(<code>ludus</code>\) that <code>cluster\-sdn\-setup</code> assumes already exists\: it creates and applies the zone when absent\, refuses an existing zone of the wrong type\, and verifies the zone is VXLAN on disk\. New <code>ludus\_install\_negative</code> Molecule scenario \(no install present\, installer disabled\) must stop at the role\'s labelled install guard\.
* New role <code>cluster\_discover</code> and play <code>cluster\-discover</code> — read the live cluster \(PVE version\, corosync membership\, block devices\, ZFS pools\, interfaces\, guests\; cluster status and node fingerprints\, storage\, users/groups/roles/realms\, pools\, SDN objects\, directory mappings and Ceph via <code>ceph\_info</code>\) and fill the inventory\'s As\-Is records \(<code>host\_vars/\<host\>/node\.yml</code>\, <code>group\_vars/proxmox\_cluster/cluster\.yml</code>\) from it\. By default it writes proposal files under <code>inventory/discovered/</code> \(never loaded\)\; <code>cluster\_discover\_write\=in\_place</code> rewrites the records themselves\. Configured values win and discovery fills the gaps unless <code>cluster\_discover\_overwrite\=true</code>\; annotations the node cannot report survive either way because disks\, pools\, guests and cluster objects are merged on their identity key\. <code>\-\-check \-\-diff</code> is a drift report and <code>cluster\_discover\_strict\=true</code> a drift gate\. Positive \(fixture\-driven render\, idempotence\, verify\) and negative Molecule scenarios\.
* Per\-role <code>meta/argument\_specs\.yml</code>\, <code>README\.md</code>\, and <code>meta/main\.yml</code> where missing \(§3\)\, including <code>cluster\_ludus\_auth</code>\.
* The <code>proxmox\_config</code> master gains <code>sdn\_range\_vnets</code> \(← the <code>sdn\_range\_vnets</code> group var\)\, so the per\-range VNets Ludus hands out are part of the single Proxmox\-fact master\. The sibling <code>get\_sybers\.lxc</code> collection reads it to validate a range\'s VNet against this declared source of truth instead of probing the node\'s live <code>/etc/pve/sdn</code>\. Nothing in this collection consumes the new key \(<code>ludus\_config</code> does not project it\)\; it is additive\.
* The whole Ludus server <code>config\.yml</code> is expressed once as two owner\-named host\-var maps on the <code>proxmox\_master</code>\, with values flowing one direction \(<code>proxmox\_config</code> \-\> <code>ludus\_config</code>\)\. <code>host\_vars/\<master\>/proxmox\_config\.yml</code> owns the Proxmox facts Ludus needs\, each a reference to its one home \(<code>cluster\_master\_node</code>\; <code>pve\_validate\_certs</code>\; <code>sdn\_vm\_storage\_pool</code> / <code>sdn\_iso\_storage\_pool</code> / <code>sdn\_zone</code> / <code>sdn\_vxlan\_tag\_base</code>\; and the host networking from the discovered <code>node</code> record\)\. <code>host\_vars/\<master\>/ludus\_config\.yml</code> is a thin projection OF <code>proxmox\_config</code> — every Proxmox\-derived key reads <code>\{\{ proxmox\_config\.\* \}\}</code> — plus the Ludus\-owned <code>ludus\_cfg\_\*</code> values in <code>group\_vars/all/ludus\.yml</code> and the vaulted <code>database\_encryption\_key</code> \(<code>inventory/secrets/ludus\.yml</code>\, split vars/vault\)\. <code>cluster\_ludus\_install</code> reconciles <code>/opt/ludus/config\.yml</code> from this <code>ludus\_config</code> map \(every key whose resolved value is non\-empty\; secret keys verified against the running server and never rewritten\; host network keys only when <code>cluster\_ludus\_install\_manage\_network\=true</code>\)\. <code>inventory/example</code> ships <code>proxmox\_config\.yml</code> / <code>ludus\_config\.yml</code> for the master and <code>secrets/ludus\.yml\.example</code>\.
* <code>\.ansible\-lint</code> \(<code>profile\: production</code>\) with a documented <code>name\[casing\]</code> waiver reconciling ansible\-lint with the house task\-naming form \(§2\, §11\, §16\)\.
* <code>\.github/workflows/release\.yaml</code> \(<code>Release collection</code>\, Standard 04\)\: on a published GitHub release\, <code>ansible/ansible\-content\-actions</code> release\.yaml publishes to Automation Hub then Galaxy from the <code>release</code> environment \(<code>AH\_TOKEN</code>\, <code>ANSIBLE\_GALAXY\_API\_KEY</code>\)\; <code>changelogs/</code> makes antsibull\-changelog the generator of <code>CHANGELOG\.md</code> with Keep a Changelog sections\, the <code>0\.1\.0</code> notes seeded into <code>changelogs/changelog\.yaml</code> and the unreleased notes carried as a fragment \(§2\, §26\, §31\)\.

<a id="changed"></a>
### Changed

* Breaking\: every role variable is now prefixed with its role name \(§18 var\-naming\)\, so callers must rename the inputs and consumed facts they set \(e\.g\. <code>sysmon\_\*</code> \-\> <code>sysmon\_linux\_\*</code>\, <code>cluster\_pb\_\*</code> \-\> <code>cluster\_pb\_store\_\*</code>\, and the <code>cluster\_secrets</code> inputs/outputs such as <code>infra\_secret</code> \-\> <code>cluster\_secrets\_result</code>\)\.
* Breaking\: roles are renamed to a <code>cluster\_\<category\>\_\<tool\></code> scheme \(variables and FQCN/<code>roles\:</code> references move with them\) — <code>cluster\_packer\_plugins</code> \-\> <code>cluster\_plugin\_packer</code>\, <code>cluster\_ludus\_patches</code> \-\> <code>cluster\_patch\_ludus</code>\, and <code>cluster\_packer\_iso\_patch</code> \-\> <code>cluster\_patch\_packer\_iso</code>\.
* Cluster playbook configuration is no longer hardcoded inline\. Facts that were embedded in <code>vars\:</code> blocks — and in several cases duplicated across plays — now live in config YAML\: cluster\-wide values consumed by the node\-targeting plays \(<code>sdn\_zone</code>\, <code>cluster\_peers</code> derived from each node\'s <code>node\.mgmt\_ip</code>\, the Ceph pool/replication and canonical <code>ceph\_osd\_tuning</code>\, and the Ceph mesh topology/<code>expected\_egress</code>\) in a new <code>inventory/group\_vars/proxmox\_cluster\.yml</code>\; per\-host storage links in each <code>inventory/host\_vars/\<host\>\.yml</code>\; and the values consumed by the <code>localhost</code> credential/vault and audit plays \(which inventory group\_vars cannot reach\) in <code>playbooks/vars/ludus\-common\.yml</code> and <code>playbooks/vars/audit\-artefacts\.yml</code>\, pulled in with <code>vars\_files</code>\. <code>cluster\-ceph\-diagnose</code> now derives its drift\-check expectations from the same <code>ceph\_osd\_tuning</code> source <code>cluster\-ceph\-tuning</code> applies\, so the two cannot diverge\. No runtime behaviour changes — values are preserved exactly\.
* Collection identity corrected to <code>get\_sybers\.cluster</code> \(was the <code>get\_sybers\.example</code> scaffold\)\; dependencies\, <code>requirements\.yml</code> pins\, the <code>meta/runtime\.yml</code> floor and every role\'s <code>min\_ansible\_version</code> are reconciled \(§2/§13\)\.
* Every <code>ansible\.builtin\.command</code> is argv\-form \(one list element per argument\, never a free\-form string\)\, so an argument that carries a space reaches the program whole and nothing is re\-split by the module\; the templated command loops carry lists\, and the <code>ludus source add</code> impersonation is a list of arguments\.
* Every play\-level <code>vars\:</code> / <code>vars\_files</code> block is gone \(standards §5\)\: the audit\-logging\, Ceph \(diagnose\, tuning\, mesh\)\, SDN\, storage\-net\, node\-repos\, node\-upgrade\, credential\, vault\, DEK\, token\, identity\, GitLab\-runner\, sources and 1Password plays read their configuration from the inventory under topic\-prefixed names \(<code>audit\_\*</code>\, <code>sdn\_\*</code>\, <code>node\_repos\_\*</code>\, <code>mesh\_\*</code>\, <code>ceph\_\*</code>\, \.\.\.\)\. No play names a host any more\: the hard\-coded master hostname became <code>hosts\: proxmox\_master</code> and <code>delegate\_to</code> uses <code>cluster\_master\_node</code>\; the Ceph mesh cutover derives its mon targets\, OSD hosts\, prefixes and bench interface from the mesh config and the live OSD tree\.
* Generated files are templates \(standards §13\)\: the FRR <code>frr\.conf</code> and the <code>storage\-mesh</code> stanza of the mesh play\, and the <code>storage\-net</code> stanzas and hotplug udev rule of the storage\-net play\.
* Loop items\, declared loop variables and Jinja loop variables are read with bracket notation \(<code>item\[\'key\'\]</code>\, never <code>item\.key</code>\)\, as the standard requires\: dot access breaks on hyphenated keys and collides with the dict methods\.
* Molecule is retargeted off the <code>quay\.io</code> CentOS image onto a throwaway\, digest\-pinned official Debian 13 container driven by the <code>community\.docker</code> driver \(PVE is Debian\)\, configured once in a shared <code>extensions/molecule/config\.yml</code> base config\. Every role has a negative scenario \(run without its live dependency it must stop at its own labelled assertion\, never crash\)\; <code>cluster\_secrets</code>\, whose host\-side logic is self\-contained\, also has a positive converge/idempotence/verify scenario with a committed fixture\. <code>community\.docker</code> is pinned in <code>requirements\.yml</code> as test\-only tooling \(§12\)\.
* Role <code>meta</code> <code>license\:</code> fields aligned to the collection\'s declared <code>AGPL\-3\.0\-only</code> \(§2\)\.
* Role defaults no longer carry site values \(standards §4c/§4d\)\: <code>cluster\_onepassword\_connect\_node</code>\, <code>cluster\_ceph\_orphan\_sweep\_pool</code>\, <code>cluster\_ludus\_install\_vm\_storage\_pool</code> / <code>\_sdn\_zone</code> / <code>\_reserved\_range\_numbers</code> reference the collection variables <code>cluster\_master\_node</code>\, <code>ceph\_pool</code>\, <code>sdn\_zone</code> and <code>ludus\_reserved\_range\_numbers</code> the inventory defines\; <code>sysmon\_linux</code> defaults are generic \(loopback\-only exclusions\, a neutral stage dir\)\; the <code>cluster\_preflight</code> group name is the documented input <code>cluster\_preflight\_cluster\_group</code> and its messages name no host\.
* Task names with a trailing variable now place the variable at the end only \(§33\)\.
* The <code>cluster\-ghost9\-pve\-token</code> play manages the scoped deploy user\, its API token\, the ACL\-anchor pool and the ACLs through the <code>community\.proxmox</code> modules \(<code>proxmox\_user</code> — which mints the token and returns its secret — <code>proxmox\_pool</code> and <code>proxmox\_access\_acl</code>\)\, authenticating via the collection\'s documented <code>PROXMOX\_\*</code> variables\. The fictional <code>get\_sybers\.infra\.proxmox\_pveum</code> module and its invented <code>get\_sybers\.infra</code> dependency are replaced by <code>community\.proxmox</code> as a real declared dependency\.
* The inventory directory is now the single config home and <code>ansible\.cfg</code> points at it\. <code>hosts\.yml</code> holds only hosts and groups \(<code>proxmox\_cluster</code>\, the new <code>proxmox\_master</code> for the Ludus node\, and a declared <code>controller</code> localhost so the controller\-side plays receive group\_vars\)\; every value the plays consume lives in <code>group\_vars/all/\<topic\>\.yml</code>\, <code>group\_vars/proxmox\_cluster/\<topic\>\.yml</code> and <code>host\_vars/\<host\>/\<topic\>\.yml</code>\. <code>inventory/cluster\.yml</code> \(a snapshot that was being parsed as an inventory source\) became <code>group\_vars/proxmox\_cluster/cluster\.yml</code>\; <code>inventory/secrets/</code> and <code>inventory/discovered/</code> are ignored as inventory sources\.
* <code>\.ansible\-lint</code> <code>var\-naming\[no\-role\-prefix\]</code> waiver justification re\-verified\: 44 offenders across nine roles\, now all named \(§15\, §18\, §28\)\.
* <code>cluster\-audit\-logging</code> no longer uses <code>meta\: end\_play</code> \(standards §4e\)\: the gate play skips its block on a rollback and the rollback branch ends the host\.
* <code>cluster\_discover</code> writes its records with an explicit owner and group — the new inputs <code>cluster\_discover\_record\_owner</code> and <code>cluster\_discover\_record\_group</code> default to the identity of the user running Ansible on <code>cluster\_discover\_delegate\_to</code>\, read natively by the render stage \(<code>setup</code>\, the <code>user</code> subset\)\.
* <code>cluster\_patch\_packer\_iso</code> resolves the build node from <code>cluster\_master\_node</code> \(the single home <code>proxmox\_config\.node</code> also reads\) instead of slurping and parsing <code>proxmox\_node</code>/<code>proxmox\_hostname</code> out of Ludus\'s rendered <code>/opt/ludus/config\.yml</code>\. The node is now an overridable input\, <code>cluster\_patch\_packer\_iso\_build\_node</code>\. The unused <code>cluster\_patch\_packer\_iso\_storage\_pool</code> \(declared but never referenced\) and <code>cluster\_patch\_packer\_iso\_config\_path</code> \(only the config\.yml re\-parse used it\) inputs are removed\.
* <code>cluster\_plugin\_packer</code> declares the plugin tree\'s mode \(<code>u\=rwX\,g\=rX\,o\=rX</code>\) alongside its owner and group\.
* <code>cluster\_preflight</code> reads the effective uid and the node name from the delegate\'s facts \(<code>setup</code>\, the <code>user</code> and <code>platform</code> subsets\) instead of running <code>id \-u</code> and <code>hostname</code>\; <code>cluster\-token\-restore\-from\-pve</code> and <code>post\-update\-reconcile</code> assert root from the user facts instead of a <code>pipe</code> lookup\.
* <code>cluster\_secrets</code> ships a <code>tasks/main\.yml</code> that refuses a bare include and names its entry points\, like every role in the collection\.
* <code>galaxy\.yml</code> <code>build\_ignore</code> now excludes <code>molecule/</code> and all non\-collection repo content \(<code>\.ansible</code>\, <code>\.github</code>\, <code>\.gitignore</code>\, <code>\.gitlab\-ci\.yml</code>\, <code>ansible/</code>\, <code>look\-into\.md</code>\, <code>tox\.ini</code>\, <code>tox\-ansible\.ini</code>\) \(§2\)\.
* <code>galaxy\.yml</code> dependencies now carry upper bounds \(<code>\>\=x\.y\.z\,\<next\-major</code>\) and declare every Galaxy collection actually used \(<code>ansible\.posix</code>\, <code>ansible\.utils</code>\, <code>ansible\.windows</code>\) \(§2\)\.
* <code>meta/runtime\.yml</code> <code>requires\_ansible</code> raised to <code>\>\=2\.16\.0</code>\, the floor every role\'s <code>min\_ansible\_version</code> agrees with \(<code>cluster\_ceph\_orphan\_sweep</code> and <code>cluster\_patch\_packer\_iso</code> declare 2\.16\) \(§2\)\.
* <code>packer\-iso\-redirect\.yml</code> is the read\-only report it had already become\: the rollback of a rewrite the role refuses to make is gone\, and the root check reads the user facts instead of shelling out\.
* <code>requirements\.yml</code> now pins the dependency collections \(<code>community\.general</code>\, <code>ansible\.posix</code>\, <code>community\.proxmox</code> and the test\-only <code>community\.docker</code> plus its <code>community\.library\_inventory\_filtering\_v1</code> transitive\) to git tags on their upstream <code>ansible\-collections</code> GitHub repositories instead of a <code>galaxy\.ansible\.com</code> source\. The whole closure is listed explicitly\, so <code>ansible\-galaxy collection install \-r requirements\.yml</code> \(CI\, the container image and <code>make deps</code>\) resolves entirely from git and never calls the Galaxy API — the install now works on managed networks that reach github\.com but block Galaxy\. The tags are the same releases Galaxy serves and stay inside the <code>galaxy\.yml</code> bounds\; <code>galaxy\.yml</code> itself is unchanged\, so published consumers resolve the dependencies from Galaxy as before\.
* <code>scripts/check\_pins\.py</code> maps a git\-sourced entry back to the collection it installs as \(the fqcn read from the repo URL\) so a git\-pinned <code>galaxy\.yml</code> dependency satisfies the bound check exactly as a Galaxy pin does\; a git tag is the version\, a commit SHA records the pin without a numeric bound check\. <code>scripts/upgrade\_pins\.py</code> already raised git pins to the newest in\-bound tag\.
* ansible\-lint <code>\-\-profile production</code> and yamllint pass across the collection — FQCN\, task\-name and variable conventions \(§11/§16/§18\) are enforced\, and the lint\-config files the hook set needs are in place\.

* The LXC tier moved to its own repository and collection\, [get\-sybers/lxc](https\://github\.com/get\-sybers/lxc) \(<code>get\_sybers\.lxc</code>\)\, which owns both the build of every hardened container and every sanctioned way of interacting with one\. Gone from here\: the roles <code>cluster\_onepassword\_connect</code> and <code>cluster\_onepassword\_item</code>\, the plays <code>cluster\-onepassword\-connect</code> and <code>cluster\-onepassword\-reflect</code>\, their Molecule scenarios\, <code>inventory/group\_vars/all/onepassword\.yml</code>\, <code>inventory/secrets/onepassword\.yml\.example</code> and <code>docs/05\-1Password\-Integration\.md</code>\. * <code>playbooks/bootstrap\-site\-vars\.yml</code> and its template — it vault\-encrypted two non\-secret values into <code>vars/site\.yml</code>\, which nothing loaded\; <code>audit\_zpool</code> and <code>audit\_min\_free\_gb</code> are plain inventory values now\.

* <code>playbooks/vars/ludus\-common\.yml</code> and <code>playbooks/vars/audit\-artefacts\.yml</code> — folded into <code>group\_vars/all</code>\.

* <code>\.gitignore</code> excludes the <code>\.ansible/</code> lint cache \(§14\)\.
* <code>ansible\.cfg</code> now sets <code>collections\_path</code> to the repo\-local\, gitignored <code>\.ansible/collections</code> directory\. With no <code>collections\_path</code> set\, <code>ansible\-lint</code> / <code>ansible\-compat</code> and <code>make deps</code> installed collections into the global <code>\~/\.ansible/collections</code>\, which then held a second copy of this collection and produced <code>Another version \.\.\. was found installed</code> duplicate\-collection warnings \(and risked plays importing stale role code\, depending on search\-path order\)\. Collections now install into the project tree\, which <code>\.gitignore</code> already excludes via <code>/\.ansible/</code>\.
* <code>cluster\-ceph\-mesh</code> wrote a mangled Jinja comment \(a bare <code>\{</code> and two lines of prose\) into <code>/etc/frr/frr\.conf</code> on every run\; the template carries a real <code>\{\# \#\}</code> comment\.
* <code>cluster\-storage\-net</code> hard\-coded <code>thunderbolt0</code> in the hotplug udev rule\; the rule is rendered for every hotplug link in <code>storage\_links</code>\.
* <code>cluster\_discover</code> — the <code>gather\_cluster</code> step that reads Ceph\'s <code>mon\_host</code> out of <code>ceph\.conf</code> wrote its <code>regex\_search</code> pattern and <code>\\1</code> backreference with doubled backslashes inside a folded \(<code>\>\-</code>\) scalar\, so the filter received literal <code>\\\\</code> sequences\. On a cluster whose Ceph section is present but whose <code>ceph\.conf</code> has no matching <code>mon\_host \=</code> line\, <code>regex\_search</code> then raised <code>\'NoneType\' object has no attribute \'group\'</code> and aborted the entire discovery run\. Written with single backslashes \(the correct spelling for a folded scalar\) the lookup returns the value on a match and <code>none</code> on no match\, matching the two sibling <code>regex\_search</code> calls in the same block\.
* <code>cluster\_pb\_store</code> preflight probes PocketBase with <code>failed\_when\: false</code> and asserts reachability\, turning an unreachable store into a labelled diagnostic instead of an uncaught <code>uri</code> error\.
* <code>command</code>/<code>shell</code> tasks that had a native\-module equivalent now use the module\; read\-only probes carry a <code>changed\_when</code> and a named lint waiver \(§8\)\.
* <code>get\_sybers\.cluster\.to\_config\_yaml</code> lost the sequence indentation the inventory\'s yamllint requires wherever PyYAML is built with libyaml \(every CI runner\, most workstations\)\: the C emitter ignores the Python\-level indentation override\. The filter now renders through PyYAML\'s pure\-Python safe dumper\, reducing Ansible\'s tagged scalars to plain values first\, so <code>cluster\-discover</code> writes the same file everywhere\.
* <code>plugins/modules/ceph\_info\.py</code> <code>RETURN</code> block was not parseable YAML \(an unquoted <code>\"\: \"</code> inside a plain scalar\)\, which broke <code>ansible\-doc</code> and <code>ansible\-test sanity</code>\.
* <code>scripts/conform</code> syntax\-check reads stdin from <code>/dev/null</code> so Ansible\'s non\-blocking\-stdio refusal can no longer be swallowed as a bogus failure\.
* <code>sysmon\_linux</code> asserts at entry that <code>sysmon\_linux\_artefacts</code> is non\-empty\, so an unstaged run fails with a clear message instead of crashing at <code>sysmon \-accepteula \-i</code> on a host that has no Sysmon package\.
